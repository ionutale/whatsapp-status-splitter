# Share All Clips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A **Share all (N)** action in the export panel that prepares every clip for the current settings and hands them to the OS share sheet in one call (WhatsApp → Status), with a guided per-clip fallback when the phone can only share one file at a time.

**Architecture:** `ExportPanel` owns a small share-all state machine (`idle → preparing → ready → sharing → idle`) layered on the existing `ExportState.runJobs` and its component-local `jobKey` cache. `share.ts` gains `canShareAll(files)` and `shareFiles(files, title)`; the page/phone layouts are untouched because the panel is already reused full-width on phones.

**Tech Stack:** Svelte 5 runes, TypeScript, Vitest browser project (Chromium, `vi.stubGlobal`), Playwright (`mobile` project, `addInitScript` stubs for `navigator.canShare`/`navigator.share`).

**Spec:** `docs/superpowers/specs/2026-10-31-share-all-design.md`

## Global Constraints

- **The OS share sheet is the only channel.** Never attempt direct WhatsApp-Status integration or photo-library writes.
- **Gesture rule:** a share call after a long prepare cannot open the sheet. Attempt the share immediately after preparing; on `NotAllowedError`, show an explicit **ready** state whose next tap shares the already-prepared files (no re-encode).
- **Visibility:** the button is shown only when file sharing is supported (`canShareFiles()`) and there are **≥ 2 clips**; a single clip keeps the per-clip Share.
- **Stale-encode guard:** the existing `jobKey` cache is the single authority. Never share a blob whose key no longer matches the current plan/bounds; re-derive jobs after every await.
- **Partial failures:** share only the successfully prepared clips, label the count ("Share 2 of 3"), leave failures retryable per clip as today.
- **Cancel:** canceling preparation shares nothing; partially encoded results stay available for per-clip Download.
- Existing per-clip Share/Download, ZIP export, batch mode, offline, and desktop behavior otherwise unchanged. No new dependencies.
- The committed design says labels/layout are the builder's call; keep the fallback inline in `ExportPanel`.

## Review Focus

- **Activation expiry after a slow prepare** — a share attempt that the browser refuses must not silently do nothing; it must land on a visible ready button whose tap opens the sheet without re-encoding. Pinned in Task 2.
- **Guided fallback progression** — when multi-file sharing is unsupported, taps must advance clip by clip, stay on the same clip after a user cancel (`AbortError`), and never skip or double-share. Pinned in Task 3.
- **Partial encode failure** — a failed clip must be excluded, not stall or poison the share, and the label must tell the truth about the subset. Pinned in Task 2.
- **Settings change mid-prepare** — a preset/bounds/crop change while encoding must never cause an old-settings blob to be shared; stale entries are dropped and, if nothing valid remains, an error is shown. Pinned in Task 2.
- **Cancel during preparation** — clicking Cancel while clips encode must result in zero share calls and retained partial results. Pinned in Task 2.

		encodeClip: () => ({ result: new Promise<Blob>((resolve) => resolvers.push(resolve)), cancel: async () => {} }),
		downloadBlob: () => {},
		makeZip: async () => fakeBlob
	});
	const share = vi.fn(async () => {});
	vi.stubGlobal('navigator', { canShare: () => true, share });

async function stubShare(page: Page, multiFileOk: boolean) {
	await page.addInitScript((multi) => {
		(window as unknown as { __shareCalls: string[][] }).__shareCalls = [];
		Object.defineProperty(navigator, 'canShare', {
			configurable: true,
			value: (data?: { files?: File[] }) => (data?.files?.length ?? 0) < 2 || multi
		});
		Object.defineProperty(navigator, 'share', {
			configurable: true,
			value: async (data: { files?: File[] }) => {
				(window as unknown as { __shareCalls: string[][] }).__shareCalls.push(
					(data.files ?? []).map((f) => f.name)
				);
			}
		});
	}, multiFileOk);
}
